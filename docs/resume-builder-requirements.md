# 本地 AI 简历生成工具：需求与实施记录

> 状态：需求访谈完成，第一版可运行原型已于 2026-07-26 完成；截至 2026-08-02 已补充七步新手引导、完整演示资料包、Windows x64 安装程序和 Intel macOS 试用包，后续随真实简历测试继续更新。

## 1. 项目目标

开发一款本地运行、通过浏览器使用的 AI 简历生成工具。第一版供个人使用，验证效果后可扩展为面向其他求职者的产品。

用户提供个人资料和求职意向后，系统解析并建立基础人才档案，再针对不同职位描述生成独立、精美且可编辑的定制简历。

## 2. 已确认的用户与场景

- 第一版：单人在自己的电脑上使用；当前也支持通过 Windows x64 或 Intel macOS 试用包交给熟人体验。
- 后续方向：产品效果理想后，可增加多用户、商业化和发布能力。
- 当前主要求职方向：
  - AI 相关岗位，如 FDE（Forward Deployed Engineer）及其他 AI 工程师岗位。
  - 证券、股票交易员岗位。
- 当前主要投递中文岗位，但需要完整支持中文、英文和中英双语简历。

## 3. 已确认的核心流程

1. 用户通过以下任一方式提供资料：
   - 手动填写。
   - 单选或多选上传旧简历及补充材料（Word、文本型 PDF、扫描 PDF 或简历图片）；系统逐文件解析并按文件名合并原文。
   - 粘贴目标岗位的 JD（Job Description，职位描述），或直接在 JD 文本框粘贴一张或多张岗位截图并通过本地 OCR 提取文字。
2. 系统解析资料并展示结构化结果。
3. 用户逐项确认、更正或补充解析结果。
4. 系统建立一份可复用的基础人才档案。
5. 系统根据不同岗位 JD 分析匹配度、优势、缺口和关键词覆盖情况。
6. 系统以基础人才档案为事实源，生成一份独立的岗位定制简历；姓名、电话、邮箱、城市、链接和照片始终读取基础档案，个人概述、目标职位、经历表述、项目顺序和技能重点按 JD 调整。
7. 用户选择生成模式：同方向跳槽以已有事实为主并过滤无关经历；跨行业转行可按“小白、入门、熟练、精通”生成个人项目、模拟项目、案例研究和技能草稿，但不得虚构公司任职、学历、证书或精确业绩，且不覆盖基础人才档案。
8. 系统每次只提出一个补充问题，并根据用户的回答动态决定下一个问题；用户可以跳过或结束追问。
9. 系统生成完整的岗位定制正文，用户可以直接编辑、手动增删模块，或选中字段交给右侧 AI 局部修改。
10. 未选中字段时，用户可让 AI 智能新增、删除或重新生成项目及其他模块；AI 修改支持撤销和恢复。
11. 用户编辑文字、调整模块顺序、切换模板和页数。
12. 用户通过页面按钮一键导出 PDF 和可继续编辑的 Word 文件；浏览器 `Ctrl+P` 作为 PDF 备用导出方式。

## 4. 已确认的功能范围

### 4.1 资料与档案

- 保存一份基础人才档案。
- 针对 AI 工程师和证券交易员等不同方向生成互相独立的定制简历。
- 支持个人照片，并允许生成有照片或无照片版本。
- 所有资料、生成结果和历史版本默认保存在本机。
- 支持一键备份与恢复本地数据，便于迁移电脑和防止数据丢失。

### 4.2 AI 与隐私

- 使用用户在设置页自行选择的 AI 服务商及其 API Key；本地 Ollama / LM Studio 通常无需 Key。
- API Key 不写死在代码中。
- 简历内容优化通过大模型 API 完成。
- 默认使用本地 OCR 解析扫描 PDF 和简历图片，优先复用已有 EasyOCR 环境。
- 当本地 OCR 效果不足时，可由用户主动选择多模态 API 作为兜底。
- 后续设计隐私模式：敏感字段可在发送 API 前替换为占位符，响应返回后在本地还原。

### 4.3 语言与版式

- 第一版操作界面只提供中文，以控制开发范围。
- 可分别生成中文版和英文版。
- 可生成中英双语混排版。
- 第一批模板方向：简洁、专业和轻创意；模板数量与具体视觉稿待确认。
- 采用受约束的模块化编辑，不实现 Canva 式自由拖拽。
- 支持编辑文字、调整模块顺序和切换模板。
- 默认生成一页简历，用户可主动选择多页。
- 页面提供一键 PDF 导出；同时保留浏览器打印作为故障兜底。
- 模板设计需兼顾网页预览、PDF 和 Word，优先选择跨格式稳定的布局。

### 4.4 版本与审核

- 自动保存每次生成和修改的历史版本。
- 可查看、复制或恢复旧版本。
- 基础人才档案与岗位定制正文分离，生成和编辑岗位版本不会覆盖基础档案。
- AI 修改支持撤销与恢复；用户可直接编辑并手动增删经历、项目、技能等模块。

## 5. 第一版明确不做

- 注册、登录、会员和支付。
- 招聘网站实时岗位抓取；第一版由用户粘贴 JD 文本。
- Canva 式任意元素自由拖拽。
- 求职信、自我介绍和面试问题生成。这些作为后续候选功能保留。
- 操作界面的中英文切换；该能力已确认为后续必做功能，但不影响第一版生成英文或中英双语简历。
- Apple Developer ID 正式签名与公证仍不在当前预算内；公开发布同时构建 Intel 与 Apple Silicon macOS 安装包，首次启动可能需要在 Finder 中右键“打开”。

## 6. 已确认的安全与兼容要求

- DeepSeek 等云端服务使用各自官方或兼容 API，由用户在设置页填写 Key；也支持本机 Ollama / LM Studio。
- 本地应用不额外设置解锁密码，依赖操作系统当前账户权限。
- 提供 ATS 稳定版与视觉设计版模板；视觉效果不能以牺牲招聘系统可解析性为代价。
- 第一版只做中文操作界面，产品名称暂用“简历工坊”，两者后续均可替换。
- 用户愿意在端到端测试阶段提供真实或脱敏旧简历和真实岗位 JD。

## 7. 待确认事项

- 模板的具体视觉样式和最终数量。
- 各 AI 服务商的模型选择、调用预算及失败时的降级策略。
- 本地数据的删除规则，以及备份包的格式与保护方式。
- Word 与 PDF 导出的版面一致性验收标准。
- 用于首轮端到端测试的真实或脱敏简历样本与目标 JD。

## 8. 第一版核心验收目标

第一版需要同时满足以下目标，不把它们拆成相互替代的选项：

1. 导出稳定：优先级最高。PDF 与页面预览高度一致；Word 保持内容、模块顺序、字体层级和整体风格一致。
2. 内容针对岗位：依据用户提供的 JD 做匹配分析和定制改写。
3. 视觉精美：提供简洁、专业、轻创意且适合跨格式导出的模板。
4. 操作简单：通过清晰的分步流程完成导入、确认、追问、生成、审核和导出。

## 9. 技术方案

- 运行形态：Windows / macOS 本机启动服务，浏览器访问 `http://127.0.0.1:8877`，不对局域网或公网开放；安装包内置本地 OCR 与 PDF 导出所需的 Chromium headless shell。
- 后端：Python 3.12 + FastAPI。
- 前端：原生 HTML、CSS、JavaScript，减少安装体积和构建依赖。
- 本地存储：SQLite；简历正文采用版本化 JSON 数据结构。
- 文件解析：`python-docx` 读取 Word，PyMuPDF/PDFPlumber 读取文本 PDF；RapidOCR 作为中文扫描件与图片的主识别引擎，低置信度时进行图像增强，EasyOCR 作为故障兜底。
- AI：统一服务商适配层支持 OpenAI 兼容协议和 Anthropic Messages 协议，DeepSeek 为默认云端选项，也支持本机 Ollama / LM Studio；提示词要求结构化 JSON 输出。同方向模式遵守事实约束，跨行业模式只允许生成明确标注的个人项目、模拟项目或案例研究。
- PDF：预览与导出共用同一份 A4 HTML/CSS，由本机 Chromium 一键打印为 PDF。
- Word：使用 `python-docx` 生成明确设置 A4、边距、字体、表格宽度和分页规则的 `.docx`。
- 备份：导出和恢复带版本号的本地 JSON 备份包，默认不包含 API Key。

## 10. 当前建议的实施原则

- 本地浏览器版优先，以缩短开发和验证周期。
- 简历内容、模板渲染与 AI 提示逻辑分离，方便未来增加模板和模型。
- 本地 OCR 优先，多模态 API 可选兜底。
- AI 生成结果先进入独立岗位草稿，用户可直接编辑、撤销或恢复，不得自动回写基础人才档案。
- 第一版聚焦“资料解析—确认补充—岗位匹配—内容优化—模板编辑—双格式导出”的完整闭环。
